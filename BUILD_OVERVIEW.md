# QuantLibAddin

This repo contains source code and examples for the QuantLibXL, QuantLibAddin, ObjectHandler, and gensrc projects.

## Directory Structure

The repo contains the following subdirectories/subprojects:
```
 QuantLib - a separate repo pointing to a snapshot of QuantLib (changes to this repo are outside our scope)
 gensrc - a python script for autogenerating source code
 ObjectHandler - an object repository
 QuantLibAddin - implements a wrapper of QuantLib using ObjectHandler
 QuantLibXL - deploys the QuantLibAddin inferface to Excel as an XLL addin
```
There are two ways to build QuantLibAddin.  One approach uses visual studio solution files which are maintained manually.  This build is supported only on Windows.  This build  is documented here:

[./README_vs_build.md](./README_vs_build.md)

The other approach uses cmake.  This build is supported on both Windows and Linux.  This build is documented here:

[./README_cmake_build.md](./README_cmake_build.md)

Other aspects of the build are documented in the `*.md` files in the QuantLibAddin directory.

The Visual Studio and cmake builds both support two kinds of builds:
- Full: run gensrc to autogenerate addin source code files
- Basic: don't run gensrc, rely on files that were generated by a previous full build

For both the Visual Studio and cmake builds , we can compile two kinds of addins:
- Excel (XLL): This build only works on Windows.
- C++: This build supports both Windows and Linux.

## Interdependencies

Traditionally, the four subdirectories comprised four separate projects which could be released separately.  The dependencies between the projects are roughly:

gensrc <- ObjectHandler <- QuantLibAddin <- QuantLibXL

For example, QuantLibAddin knows about ObjectHandler, but ObjectHandler does not know about QuantLibAddin.

Imagine an end user who downloads source tarballs for gensrc and ObjectHandler.  That user might not be aware of the existence of QuantLibAddin.  They would not expect for the term QuantLibAddin to arise anywhere in the ObjectHandler build.

On a related note:
- QuantLibAddin and QuantLibXL depend on QuantLib.  ObjectHandler does not depend on QuantLib and the ObjectHandler build should not "know about" QuantLib.
- QuantLib, ObjectHandler, QuantLibAddin and QuantLibXL all depend on boost.  In the Visual Studio build: QuantLib has its own props file pointing to boost.  ObjectHandler has another, which is shared by QuantLibAddin and QuantLibXL.
